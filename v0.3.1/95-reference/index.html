TypeAgnosticSerialisation.SerdeContext — Type
SerdeContext(modules; opaque = (), functions = (), dicts = (), validate = false)
SerdeContext(single_module::Module; opaque = (), functions = (), dicts = (), validate = false)
SerdeContext(; modules = (), opaque = (), functions = (), dicts = (), validate = false)

The state threaded through every encode/decode call. It holds five things:

  • modules: the allowlist used to resolve __type__ tags back to concrete types. A tag may only name a type defined in one of these modules (or in a submodule of one); anything else errors. A single Module is accepted directly, or any iterable of modules. Base and Core are not trusted as a whole: unless listed, only their plain data types and containers resolve — the numbers, String, Symbol, Char, Nothing, Missing, Array, Tuple, NamedTuple, Pair, Dict, IdDict, the ranges, Some, Val, the type objects, and every abstract type. Listing Base or Core in modules trusts all of that module.
  • functions: the named functions that may decode. A value whose type is a singleton subtype of Function — a named function such as sin, or an anonymous function with no captures — decodes only if it is in this list, in both decode modes and from any module, listed or not. The default is empty: no function decodes.
  • dicts: the dict types, other than Dict and IdDict, that may decode. Name each by its type, such as OrderedDict; the name admits every parameterisation of it. The type must still be defined in a module of modules. The default is empty: a dict decodes only into Dict or IdDict.
  • opaque: a collection of types that are not serialised structurally. A value whose type is (a subtype of) one of these is replaced by a placeholder on encode and rebuilt with its no-argument constructor T() on decode. Use it for live, non-data objects (open files, solver models, …) you want to skip while still round-tripping the surrounding data.
  • validate: chooses the decode strategy. true rebuilds each struct through its own constructor (running all validation); false builds directly with Julia's new (no validation). See from_json and from_json_direct.

A dict decodes only into Dict, IdDict or a type of dicts, even when Base is listed: the decode calls T() and setindex! with the keys and values of the document, and another dict type (such as the type of ENV) can act on the system. Name in dicts only types whose setindex! only stores data.

You rarely build one by hand — to_json, from_json and from_json_direct construct it for you from the same keyword arguments.

Warning

The allowlists limit what a document can name. They do not make a document from an untrusted source safe to load: a listed type or function can still act on the field values that the document gives it. Load only documents that you wrote yourself.

TypeAgnosticSerialisation.decode — Method
decode(tree, ctx::SerdeContext) -> value
decode(tree, hint, ctx::SerdeContext) -> value

Reconstruct a Julia value from a plain tree produced by encode — the exact inverse. hint is the same statically-known type used on the encode side: a tagged {"__type__": …} envelope carries its own type, while an untagged payload is decoded against the (necessarily concrete) hint. The two-argument form uses hint = Any.

Every type named by a __type__ tag must be reachable from the context's module allowlist; there is no eval of strings from the tree. ctx.validate selects how structs are rebuilt — through their constructor (validated) or via new (direct). See SerdeContext.

julia> ctx = SerdeContext();

julia> decode(encode([1.0, 2.0, 3.0], ctx), ctx)
3-element Vector{Float64}:
 1.0
 2.0
 3.0

TypeAgnosticSerialisation.encode — Method
encode(value, ctx::SerdeContext) -> plain tree
encode(value, hint, ctx::SerdeContext) -> plain tree

Lower a Julia value to a plain tree — nested Dict{String,Any}, Vector{Any} and scalars that any JSON/TOML/… layer can render. This is the dependency-free core of the package; to_json is just encode followed by JSON.json.

hint is the statically-known type at this position (a field's declared type, an array's element type, …). When the hint is already concrete the reader can infer the type, so the bare structural payload is emitted; otherwise the value is wrapped in a self-describing {"__type__": …, "__value__": …} envelope carrying the full concrete type (including type parameters). The two-argument form uses hint = Any, so the top level is always tagged.

Invert with decode.

julia> ctx = SerdeContext();

julia> tree = encode((1, "two", :three), ctx);

julia> decode(tree, ctx)
(1, "two", :three)

TypeAgnosticSerialisation.from_json — Method
from_json(str; modules = (), opaque = (), functions = (), dicts = ()) -> value

Read a JSON string produced by to_json back into a Julia value, validated: every struct is rebuilt through its own constructor, so all inner-constructor / @argcheck invariants run and a tampered or inconsistent document is refused. This is the recommended, default loader.

It requires a constructor that can be replayed from the fields — positional in declaration order, or keyword by field name. A type whose constructor cannot be replayed fails loudly; mark it opaque or use from_json_direct for those. modules is the resolution allowlist (a bare Module is accepted); only types defined in it — plus the plain data types and containers of Base/Core — can be named. functions lists the named functions that may decode; the default is empty, so no function decodes. dicts lists the dict types, other than Dict and IdDict, that may decode. See SerdeContext for the exact rules.

The validation runs the constructors of the listed types on the values that the document gives. It checks the invariants of your own data; it does not make a document from an untrusted source safe to load. Load only documents that you wrote yourself.

Needs the JSON package: load it with import JSON first. See also from_json_direct for the non-validating counterpart.

TypeAgnosticSerialisation.from_json_direct — Method
from_json_direct(str; modules = (), opaque = (), functions = (), dicts = ()) -> value

Read a JSON string produced by to_json back into a Julia value, directly: each struct is built field-by-field with Julia's own new (via Expr(:new)), bypassing all constructors. This reconstructs any struct — even one with no usable constructor — and is still type-safe (new type-checks and converts every field against its declared type, so a mismatch throws and can never corrupt memory), but it runs no user validation.

Use it for JSON you produced and trust, or for types whose constructor cannot be replayed from its fields. When you want invariants enforced on load, use from_json instead. modules/opaque/functions/dicts behave exactly as for from_json.

TypeAgnosticSerialisation.to_json — Method
to_json(value; modules = (), opaque = (), kwargs...) -> String

Serialise value to a JSON string that carries enough type metadata to rebuild the exact concrete type later — without knowing the type up front. Equivalent to encode followed by JSON.json; any extra kwargs (e.g. pretty = 2) are forwarded to JSON.json.

Needs the JSON package: load it with import JSON first.

modules is the allowlist recorded for the human reader's benefit and used when the argument list is shared with the loaders — pass the module(s) that define your types (a bare Module is fine). opaque lists types to skip structurally (see SerdeContext); encoding a live, non-data value that is not marked opaque fails loudly rather than emitting a broken artifact.

Read back with from_json (validated) or from_json_direct.

TypeAgnosticSerialisation.to_msgpack — Method
to_msgpack(value; modules = (), opaque = ()) -> Vector{UInt8}

Serialise value to compact MessagePack bytes. The bytes hold the same plain tree that to_json writes, so they carry the same type metadata. MessagePack has no 16-bit float, so a Float16 is stored as the (exactly equal) Float32 and narrowed back on decode.

Needs the MsgPack package: load it with import MsgPack first. Read back with from_msgpack (validated) or from_msgpack_direct. modules and opaque behave as for to_json.

TypeAgnosticSerialisation.to_toml — Method
to_toml(value; modules = (), opaque = (), kwargs...) -> String

Serialise value to a TOML string. The top level is always the tagged {"__type__": …, "__value__": …} envelope, so it is always a valid TOML table. Extra kwargs (e.g. sorted = true) are forwarded to TOML.print.

Needs the TOML standard library: load it with import TOML first. Read back with from_toml (validated) or from_toml_direct. modules and opaque behave as for to_json.

source
TypeAgnosticSerialisation.to_yaml — Method
to_yaml(value; modules = (), opaque = ()) -> String

Serialise value to a YAML string. The document is the same plain tree that to_json writes, so it carries the same type metadata; all strings are quoted, so no string can be re-read as a number, boolean, date or null.

Needs the YAML package: load it with import YAML first. Read back with from_yaml (validated) or from_yaml_direct. modules and opaque behave as for to_json.
